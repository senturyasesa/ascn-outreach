# ONBOARDING — руководство для технического специалиста

Практическое руководство по развёртыванию, добавлению аккаунтов и эксплуатации
системы ASCN Outreach. Читай сверху вниз при первом знакомстве.

---

## 1. Как устроена система

```
┌─────────────────────────── VPS (Linux) ───────────────────────────┐
│                                                                    │
│  ascn-outreach.service   → Flask-дашборд (порт 8765)               │
│  ascn-daily.service      → демон дневной рассылки (daily_sender)   │
│  ascn-notify.timer       → проверка ответов каждые 15 мин          │
│  cron report.py          → почасовые отчёты в Telegram-бота        │
│                                                                    │
│  data/  ← все данные (сессии, база, ключи, состояние)              │
└────────────────────────────────────────────────────────────────────┘
        │                                            │
     Telethon                                   Telegram-бот
     + SOCKS5-прокси                            (уведомления, отчёты)
        │
   Telegram API
```

**Ключевые модули:**
| Файл | Назначение |
|---|---|
| `app.py` | веб-дашборд (Flask), маршруты, онбординг |
| `ui.py` | HTML-шаблоны страниц |
| `tg.py` | подключение аккаунтов, чтение/отправка (Telethon) |
| `campaign.py` | рендер сообщений, лимиты, AI-рерайт |
| `send_campaign.py` | движок ручной рассылки |
| `daily_sender.py` | демон дневной рассылки (распределение по дню) |
| `spambot.py` | самодиагностика через @SpamBot + заморозка |
| `notify_replies.py` + `check.py` | проверка ответов лидов |
| `alerts.py` | уведомления о флуде в бота |
| `report.py` | отчёты в бота |
| `errors_map.py` | классификация ошибок Telegram |
| `vault.py` | шифрование хранилища |

## 2. Добавление аккаунтов — ГЛАВНОЕ

> Это самая нетривиальная часть. Ниже — всё, что нужно знать, чтобы не потерять
> аккаунты.

### 2.1. Почему НЕ работает логин по SMS-коду

С **18 февраля 2023** Telegram на уровне сервера запретил сторонним клиентам
(не официальным приложениям) получать код входа по SMS. При попытке войти через
свой `api_id`:
- код приходит **только в уже авторизованную официальную сессию** (в чат «Telegram»),
- на симку **не приходит**,
- у аккаунтов, крутившихся в userbot-панелях (telepilot и т.п.), вход по коду
  глушится полностью: `SentCodeTypeApp` + `next_type=None`.

**Вывод:** логинить аккаунты по номеру+коду через этот софт нельзя. Используем **tdata**.

### 2.2. Основной способ — через tdata (opentele)

**Идея:** аккаунт логинится в официальном **Telegram Desktop**, оттуда берётся
папка `tdata` и конвертируется в `.session` Telethon **без запроса кода**.

**Пошагово:**
1. Залогинь аккаунт(ы) в Telegram Desktop (до 3 штук на один клиент — лимит бесплатного Desktop).
2. Закрой Telegram Desktop (крестик, **НЕ Logout** — см. 2.4).
3. Скопируй папку tdata:
   - macOS: `~/Library/Application Support/Telegram Desktop/tdata`
   - Windows: `C:\Users\<user>\AppData\Roaming\Telegram Desktop\tdata`
4. Конвертируй через `opentele` (пример):
   ```python
   import asyncio
   from opentele.td import TDesktop
   from opentele.api import UseCurrentSession, APIData

   async def main():
       tdesk = TDesktop("путь/к/tdata")
       for acc in tdesk.accounts:
           api = APIData(api_id=ТВОЙ_API_ID, api_hash="ТВОЙ_API_HASH",
                         device_model="Desktop", system_version="Windows 10",
                         app_version="4.9.0")
           client = await acc.ToTelethon(f"out_{acc.UserId}.session",
                                         UseCurrentSession, api=api)
           client.session.save()
   asyncio.run(main())
   ```
5. Залей `.session` в `data/` на сервере.
6. Пропиши прокси в `data/proxies.json` и добавь имя в `data/accounts.json`.
7. Проверь живость (см. 2.6).

### 2.3. opentele под свежий Python/Desktop

`opentele` может ломаться на Python 3.13 и новых версиях Telegram Desktop.
Если ловишь ошибки импорта или «No account has been loaded» — нужны правки:
- `utils.py`: в `crossDelete` добавить `"__firstlineno__"`, `"__static_attributes__"`.
- `td/tdesktop.py`: `kMaxAccounts` поднять с 3 до 10 (если у тебя >3 аккаунтов в tdata).
- `td/account.py`: в `readMapWith` не падать на неизвестных ключах map
  (обернуть в try, `readMtpData()` всё равно вызвать — authKey в отдельном файле).

### 2.4. КАЧЕЛИ — главная ловушка

**Проблема:** Telegram Desktop бесплатно держит максимум **3 аккаунта**. Аккаунт
на сервере и в Desktop делят **один ключ авторизации** (при `UseCurrentSession`).
Если сделать **Logout** в Desktop (или залогинить новых, вытеснив старых) —
серверная сессия **умирает**.

**Правило:** залогинил аккаунт → взял tdata → **НИКОГДА не делай Logout и не
открывай его в Desktop заново**. Просто закрой программу. Пока не разлогиниваешь —
серверная сессия живёт бессрочно.

Нужно больше 3 аккаунтов — используй **вторую portable-копию** Telegram Desktop
(отдельная папка tdata) или заводи партиями, не трогая уже подключённые.

### 2.5. Независимые сессии (обход качелей)

Чтобы аккаунт на сервере **не зависел** от Desktop, делается независимая сессия
через `CreateNewSession` — новый ключ авторизации, отдельный от tdata:
```python
client = await acc.ToTelethon("indep.session", CreateNewSession,
                              api=APIData(...), password="ОБЛАЧНЫЙ_ПАРОЛЬ_2FA",
                              proxy=proxy)
```
- Код не запрашивается (авторизуется через живую tdata-сессию).
- При включённом **2FA нужен облачный пароль** аккаунта.
- ⚠️ На практике независимость может не пережить Logout родительской сессии —
  надёжнее правило «не разлогинивать» (2.4).

### 2.6. Проверка живости аккаунта

Открыть аккаунт через прокси и дёрнуть `get_me()`. Важно: делать с **таймаутом**
(зависшая/мёртвая сессия может висеть на `connect()` бесконечно):
```python
import subprocess
r = subprocess.run(["venv/bin/python", "one.py", "ИмяАкка"],
                   capture_output=True, text=True, timeout=35)
```
`signal.alarm` для сокетов ненадёжен — используй `subprocess timeout`.

**«database is locked»** ≠ смерть аккаунта. Это временный конфликт: два процесса
(рассылка и проверка ответов) открыли один `.session`. Повторить через пару секунд.

### 2.7. Прокси

Каждому аккаунту — свой SOCKS5 в `data/proxies.json`:
```json
{ "ИмяАкка": "socks5://user:pass@host:port" }
```
Идеально 1-2 аккаунта на прокси. Гео прокси должно совпадать с регионом номера.

### 2.8. Чёрный список

Аккаунты в `data/blacklist.json` **никогда** не трогаются рассылкой (личные,
служебные). Формат `{ "@username": user_id }`.

## 4. Запуск рассылки

1. **Текст** — `data/broadcast.txt` (единый режим) либо колонка в базе (персонально).
2. **Лимиты** — в дашборде «Темп и дневные лимиты». ⚠️ Сумма лимитов должна быть
   **выше** дневной цели (с запасом на фейлы), иначе не доберёшь.
3. **Дневной режим** — задаёшь цель (например 50), демон растягивает по окну
   (09:00–22:00 МСК по умолчанию, `WIN_START`/`WIN_END` в `daily_sender.py`) и
   распределяет между аккаунтами round-robin с учётом лимитов.
4. Прогретые старые аккаунты держат больше (лимит 15-16), свежие — меньше (4-5),
   иначе свежие ловят флуд.

**AI-рерайт** (`data/rewrite.json`): в едином режиме каждое сообщение уникализируется
через OpenRouter — антиспам. Длинные тире всегда вычищаются.

## 5. Автоматика

- **@SpamBot-заморозка** (`spambot.py`): аккаунт словил флуд → ставится в очередь →
  демон идёт к @SpamBot → при ограничении жмёт «This is a mistake» и морозит до даты
  (`data/freeze.json`) → аккаунт исключается из ротации → авто-возврат по сроку.
- **Проверка ответов** (`ascn-notify.timer`, каждые 15 мин): ловит ответы лидов,
  шлёт в бота, свежие лиды проверяются первыми.
- **Отчёты** (cron `report.py`): почасовые сводки в бота.

---

## 6. Работа с ответами

Вкладка **«Ответы»** в дашборде (`/inbox`):
- список ответивших (ник, аккаунт, текст, свежие сверху),
- клик → диалог с историей + поле ответа,
- ответ уходит клиенту **с того же аккаунта**, которым писали.

## 7. Systemd — управление

```bash
systemctl status  ascn-daily.service       # статус демона рассылки
systemctl restart ascn-outreach.service    # перезапуск дашборда
journalctl -u ascn-daily.service -f        # логи демона в реальном времени
systemctl list-timers | grep notify        # когда следующая проверка ответов
```

> Если останавливал таймер/сервис для диагностики — **не забудь вернуть**
> (`systemctl start ...`), иначе, например, перестанут проверяться ответы.

## 8. Траблшутинг

| Симптом | Причина / решение |
|---|---|
| Аккаунт «не авторизован» | сделали Logout в Desktop (качели) — перезалить через tdata |
| «database is locked» | конфликт процессов на сессии — повторить через пару секунд |
| Аккаунт зависает на подключении | мёртвая сессия — проверять с `subprocess timeout` |
| «Too many requests» (PeerFlood) | спам-лимит — @SpamBot заморозит сам; снизить лимит аккаунта |
| `ALLOW_PAYMENT_REQUIRED` | получатель включил платный приём (Stars) — лид пропускается |
| Мало доставляется | проверь сумму лимитов ≥ цели; много платных лидов в базе |
| SSH рвётся (`banner exchange`) | сервер под нагрузкой telethon-коннектов — зайти коротко/через nohup |
| Ответы не приходят | проверь `systemctl is-active ascn-notify.timer` |
